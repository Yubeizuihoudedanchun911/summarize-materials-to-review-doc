# 文件生成与验收规范

## 1. 默认输出

```text
review-output/
├── 00-来源与证据台账.md
├── 01-全量材料汇总稿.md
├── 02-述职正式稿.md
├── assets/
├── build_document.*
└── 姓名-述职文件.docx
```

用户只要单一产物时可以减少文件，但仍要在内部完成来源清单、证据台账和 QA。

## 2. 内容验收

- 大纲标题按输入顺序出现，未授权的章节重排为零。
- 每条核心语句都能在正式稿定位。
- 每个挑战都有背景、难点、个人判断、真实方案比较、取舍、个人动作和结果边界。
- 每个数字能回到证据台账；时间窗、样本或口径缺失时保留 `待取数`。
- 当前生产、阶段测试、离线实验、历史项目和未来规划没有混写。
- 没有把团队整体成果改写成个人独占成果。
- 自然化前后主张数量和含义一致，没有新增事实。

## 3. DOCX 技术验收

1. 检查文件是合法 ZIP/OOXML 包，例如运行 `unzip -t <file.docx>`。
2. 检查标题层级、页眉页脚、页码、图片替代文本和表格表头。
3. 检查表格总宽不越过正文区域，固定列宽之和与可用宽度一致。
4. 检查表格行不被异常拆分，表头跨页时能重复。
5. 检查双图表格两列等宽、图片等高、标题对称、单元格垂直居中。
6. 对照图表清单核对实际展示的图和表，不用 DOCX 媒体文件数量代替。
7. 运行可访问性检查；问题应为零或有明确说明。

## 4. 页数与视觉验收

- 将最终 DOCX 渲染为 PDF，用 `pdfinfo` 读取真实页数和纸张尺寸。
- 将每一页渲染为图片并逐页查看，不能只看首页或文本提取结果。
- 检查缺字、裁切、重叠、孤立标题、表格断裂、图片模糊和页码异常。
- 检查每页信息密度；大面积空白通常说明分页或内容分配需要调整。
- 控页失败时先压缩重复内容和重排图表，再调整间距，不先缩小正文和图中文字。

任何内容或版式修改后都重新生成并检查最终 PDF。旧截图和旧页数不能作为新版本证据。

## 5. 在线文档验收

只有用户明确授权上传目标、位置和密级后，才执行外部写入。默认新建文档，不覆盖原文。

上传后：

1. 读取资产信息，核对标题、类型、创建人和密级。
2. 回读正文，核对关键标题、核心语句、数字、表格和图片节点。
3. 导出在线版本 PDF，重新检查页数和全部页面。
4. 记录在线转换差异。本地 DOCX 的页数和断页不能代替在线结果。

若在线转换丢图、破坏表格或超过页数限制，不能把“上传成功”当成交付完成。

## 6. 验收场景

| 场景 | 正确行为 |
| --- | --- |
| 多份材料中的同一指标冲突 | 保留差异并要求口径，不选择更好看的数字 |
| 长稿需要压到页数上限 | 保留大纲和核心判断，先删重复背景与材料摘抄 |
| 模板包含成对图片 | 使用等宽双列表格和等高图片 |
| 只有代码能证明实现 | 写成工程实现，不升级为生产上线或业务收益 |
| 指标只有离线结果 | 标明离线、样本和版本，不写成大盘改善 |
| 用户要求上传在线文档 | 先确认目标与密级，新建后回读并导出 PDF 验证 |

## 7. 完成报告

只陈述已验证结果：输出文件或链接、页数、完成的检查、保留的大纲与核心语句、仍为 `待取数` 的项目、无法验证的环境限制。
