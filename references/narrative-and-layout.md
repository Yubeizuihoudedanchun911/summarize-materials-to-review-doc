# 汇总、叙事与排版规范

## 1. 从材料提炼主线

用一句话回答：述职人在什么约束下，把什么问题从什么状态推进到什么状态，并形成了什么可复用能力。每一章都服务这条主线，不按文件顺序或项目时间简单拼接材料。

开头优先给出角色、范围和结果。结尾回到角色变化、形成的能力、仍未闭环的问题和下一步，不写泛化的乐观口号。

## 2. 每个挑战的结构

1. **背景：** 只保留理解问题所需的场景和约束。
2. **难点：** 说明为什么常规方案无法同时满足目标。
3. **我的判断：** 写清如何定义边界和优先级。
4. **方案比较：** 比较真实候选方案的收益、代价和适用范围。
5. **选择与代价：** 说明采纳什么、主动放弃什么、为何值得。
6. **我的工作：** 用动作、对象、难题和责任边界证明个人贡献。
7. **结果与边界：** 给出结果，并明确离线、阶段和生产口径。

一句话公式：

> 在 [约束] 下，我判断 [核心矛盾]。比较 [候选方案] 后选择 [方案]，主动承担 [代价]，完成 [关键动作]，最终得到 [结果]；[尚未验证部分] 仍按计划或待取数表述。

## 3. 正反例

不合格：

> 我建设了向量检索、关键词检索、重排、知识图谱和评测平台，全面提升了系统效果。

合格：

> 资料持续变化，单路向量召回容易漏掉专有名词，直接扩大候选集又会增加延时。我比较了关键词、向量和完整图检索，最终选择关键词与向量并行召回，再用统一排名融合。这个选择增加了离线索引成本，但把线上路径限制在固定预算内。我负责召回契约、融合策略和失败降级；效果数字只引用有周期和样本的评测记录。

## 4. 从全量稿压缩到正式稿

先按用户给出的页数上限分配页面，再改文案。上限为九页时可参考：

| 页面 | 主要任务 |
| --- | --- |
| 1 | 个人定位、职责范围、最重要结果 |
| 2 | 能力或项目演进主线 |
| 3-6 | 核心项目与主要挑战 |
| 7-8 | 质量、评测、影响力或剩余挑战 |
| 9 | 能力映射、发展规划、数据边界 |

按顺序压缩：

1. 删除重复背景、标题复述和同义结论。
2. 把技术清单收敛为“为何选、放弃什么、承担什么代价”。
3. 把三项以上的候选方案、阶段或职责改成表格。
4. 把多段结构说明改成一张图和一段判断。
5. 合并次要案例，保留最能证明能力的一个。
6. 最后微调段前后距和图片尺寸，不靠不可读字号硬塞。

不得优先删除：核心语句、挑战本质、候选方案、关键取舍、个人动作、关键结果和证据边界。

## 5. 版式语言

- 每页只承担一个主要问题，标题层级沿用大纲。
- 结果数字使用克制的强调色；同一页通常不超过两组高亮。
- 引用框只放一句核心判断或取舍。
- 三项以上的精确映射或对比使用表格；复杂结构、流程、状态或时间线使用图。
- 图与正文不重复全部信息，正文解释选择和边界。
- 双图使用两列等宽表格：单元格等宽、图片等高、水平和垂直居中、标题位置对称。
- 继承模板字号。模板缺失时，正文建议不低于 9pt，表格不低于 7.5pt。
- 内容稳定后再插入显式分页，避免用空行垫页。

## 6. 自然化表达

- 需要归因时使用“我判断、我选择、我负责、我推动”，不要让“我们”掩盖个人责任。
- 删除“赋能、引领、全面提升、意义重大、展望未来”等无证据拔高。
- 不强行凑三点，不连续使用相同句式，不在每段结尾重复“形成闭环”。
- 保留技术名词、数字、日期、专有名称和必要限定词。
- 自然化前后逐条对照证据台账，任何新增或丢失的主张都视为错误。
